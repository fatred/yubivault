# LoadConfig

# Function and scope

`LoadConfig(homeDir string) (*AppConfig, error)` lives at `main.go:102-137` and is the single reader of `<homeDir>/.yubivault/config.yml` (`main.go:103`, directory-name constant `main.go:100`). Its scope is: open the file, decode exactly one YAML document into `AppConfig` with unknown keys rejected, reject a second document, reject a config whose three always-required fields are empty, and otherwise hand back a populated struct. It does not resolve paths, check file modes, validate URL schemes, or check the mode-specific fields — those are `requireForMode` (`main.go:142-153`), called by `run` at `main.go:456`.

Success value is a fresh `*AppConfig` built at `main.go:113` and returned at `main.go:136`; every error path returns `nil` config (`main.go:106, 116, 118, 124, 131, 134`).

# Inputs and outputs

Input is one string, `homeDir`, supplied by `run` from `os.UserHomeDir()` (`main.go:448, 452`). LoadConfig never validates or creates it, and there is no flag, environment variable, or XDG-style override — the path is always `filepath.Join(homeDir, ".yubivault", "config.yml")` (`main.go:103`). The operator-facing contract for that file is documented at `README.md:47-77` (directory `chmod 700`, `chmod 600` on the key).

Output is `*AppConfig` with nine string fields, each carrying an exact lowerCamelCase yaml tag (`main.go:30-39`): `vaultAddr`, `certAuthName`, `certAuthMount`, `certAuthPemFile`, `certAuthKeyFile`, `openscPath`, `yubikeySerial`, `yubikeyPivSerial`, `yubikeyCertCN`. Fields absent from the YAML stay the zero string; values are stored verbatim, with no trimming or normalization. The accepted key set is therefore closed: the retired `yubikeyPivIndex`/`yubikeyPivLabel` named in the comment at `main.go:110-111` and any typo are rejected (asserted at `main_test.go:183-185`, documented at `README.md:77`).

Three fields are mandatory at this layer: `VaultAddr` (`main.go:130-132`) and then `CertAuthName`, `CertAuthMount` (`main.go:133-135`). Both messages are constants that carry no path, no home directory and no value. Mode-specific requirements are deliberately not here; `requireForMode` covers `certAuthPemFile`/`certAuthKeyFile` for `-local` and `openscPath`/`yubikeyPivSerial` for `-yubi` (`main.go:142-153`).

# Invariants

Open failure is passed through unchanged (`main.go:104-107`), so the caller sees `os.Open`'s `*fs.PathError` *including the config path* — the opposite of `readPrivateKey`, which strips the path with `pathErrCause` for the key file (`main.go:183-202`, `main.go:205-211`, policy comment `main.go:176-178`).

Unknown keys are fatal in document one only: `decoder.KnownFields(true)` (`main.go:112`) applies to the struct decode at `main.go:114`, and the library documents that this check applies to mappings decoded into structs (`go.yaml.in/yaml/v3@v3.0.5/yaml.go:106-110`; version pinned at `go.mod:9`). The resulting error is a `*yaml.TypeError` such as `field yubikeyPivIndex not found in type main.AppConfig`, wrapped with the path by `%w` at `main.go:118`.

An empty decoder input is special-cased: `errors.Is(err, io.EOF)` yields `<path> is empty` (`main.go:114-117`), matching the library's `io.EOF` when the parser produces no node (`yaml.go:117-123`). Everything else — mistyped scalars, duplicate keys, malformed YAML — becomes `<path>: <err>` (`main.go:118`); the message text itself is generated by the library.

Single-document enforcement is a second `Decode` into a `yaml.Node` that must return `io.EOF` (`main.go:120-125`). Because the target is a Node and not a struct, this probe checks only "is there a second document", never its content, so a second document's keys bypass `KnownFields` entirely (comment at `main.go:120-121`; asserted for the unknown-key-in-second-document case at `main_test.go:186`). Reproduced against the pinned library version: a trailing `---` with no content still produces a non-`nil` second decode (a Document node) and is rejected — the case covered by `main_test.go:186`; a `...` stream terminator produces `io.EOF` and is accepted; a malformed second document produces a non-EOF parse error (observed message `yaml: line 3: did not find expected node content`) and is therefore *rejected with the generic single-document message, the cause discarded* by `main.go:123-124`.

The decode target is a newly allocated struct (`main.go:113`), so no stale values can survive a failed load, and the deferred `file.Close()` error is discarded (`main.go:108`). The bytes decoded are the bytes of the descriptor opened at `main.go:104`: no re-open, no `Stat`, no permission check on `config.yml` — the 0o077 group/other rejection exists only for the private key (`main.go:193-195`). Finally, after `LoadConfig` returns, the struct is read-only in this package: every downstream use is a field read or a pointer pass (`main.go:130, 133, 157, 161, 169, 262, 278-279, 301, 306, 398`).

# Assumptions

`homeDir` must be a usable home directory containing `.yubivault/config.yml`; the function neither creates nor verifies it (`main.go:102-107`; setup instructions at `README.md:49-54`; the harness's directory-missing case is only asserted as an error at `main_test.go:121-127`). The file is assumed operator-authored UTF-8 YAML; a leading BOM is tolerated by the parser (observed in a scratch run against v3.0.5, no in-repo coverage).

`KnownFields` semantics are assumed as implemented: struct decodes only (`yaml.go:106-110`), which is exactly why the explicit second-document rule exists (`main.go:120-125`) and why the probe must use `!errors.Is(err, io.EOF)` rather than inspecting the node.

No scheme validation is intentional, per the comment at `main.go:126-129`: an `https` handshake is what makes `http://` fail safely, and `http://localhost:8200` stays usable for local dev; emptiness is the only test (`main.go:130`). The value reaches `vault.WithAddress` through `newVaultClient` (`main.go:326-347`, called at `main.go:169` and `main.go:306`).

Field semantics are only partly visible here: `certAuthPemFile`/`certAuthKeyFile` are names relative to `<homeDir>/.yubivault`, established by the callers that join them (`main.go:157, 161`; `README.md:63-64`), and `openscPath` is expected to be an absolute module path consumed directly as `crypto11.Config.Path` (`main.go:278`; `README.md:67-69`). `yubikeySerial` is display-only for the PIN prompt (`main.go:262`); `yubikeyPivSerial` is the PKCS#11 token serial (`main.go:279`, `README.md:82`); `yubikeyCertCN` is optional and used for credential selection on the card (`main.go:301`).

Embedding the config path in three of the four error strings (`main.go:116, 118, 124`) is assumed acceptable because the config path is not secret; the stricter path-free policy in this package is scoped to the key file (`main.go:176-178, 183-202`).

# Calls

`filepath.Join` (`main.go:103`) — no error. `os.Open` (`main.go:104`) — error returned unchanged (`main.go:105-107`). `file.Close` via defer (`main.go:108`) — error discarded. `yaml.NewDecoder` (`main.go:109`) — no error; `(*yaml.Decoder).KnownFields` (`main.go:112`) — no error. `(*yaml.Decoder).Decode` into `*AppConfig` (`main.go:114`) — `io.EOF` mapped to the empty-file message, all other errors wrapped with the path by `%w` so `errors.Is`/`errors.As` still reach the `*yaml.TypeError` or parse error. `(*yaml.Decoder).Decode` into `*yaml.Node` (`main.go:123`) — any non-EOF outcome is condensed into one constant message, so the underlying cause is deliberately not propagated. `errors.Is` (`main.go:115, 123`) — boolean only. `fmt.Errorf` (`main.go:116, 118, 124, 131, 134`) — builds every returned error. `(*AppConfig).requireForMode` is not called here; `run` calls it immediately afterwards (`main.go:456`).

# Callers and shared state

Production caller is `run` only (`main.go:452`), after `-version` short-circuits (`main.go:439-442`) and after the `-local`/`-yubi` exclusivity check (`main.go:444-446`); `run` returns LoadConfig's error unchanged to `main` (`main.go:453-455`, `main.go:423-426`). Tests are the other callers: `TestLoadConfig_FileNotFound` (`main_test.go:121-127`), `TestLoadConfig_ValidFile` (`main_test.go:129-151`), `TestLoadConfig_RejectsMissingAuthFields` (`main_test.go:153-163`) and `TestLoadConfig_Rejects` (`main_test.go:179-199`, fixture helper `writeConfig` `main_test.go:166-177`). I ran `go test -run 'TestLoadConfig|TestRequireForMode' -v`: all pass, including the empty-second-document subcase, so the `---` rejection claimed above is the tested behaviour of the pinned library, not just a reading of the code.

Shared state is only the config file itself plus the `configDirName` constant, which `CreateLocalVaultClient` reuses to build the cert and key paths (`main.go:100, 157, 161`). The returned struct fans out to five consumers: `requireForMode` (`main.go:456`), `CreateLocalVaultClient` (`main.go:480 -> 155-174`), `resolvePin`/`ReadPin` for the PIN prompt label (`main.go:262`), `CreateYubikeyVaultClient` for the PKCS#11 module path, token serial, CN selection and Vault address (`main.go:278-279, 301, 306`), and `AuthenticateAndGetToken` for the cert role name and mount path (`main.go:398`). No package-level state is mutated: `Version` (`main.go:28`) is untouched and the decoder and file handle are function-local.

# Open questions

Concurrent modification of `config.yml` between `os.Open` and decode is unexercised: the decoder streams from the descriptor opened at `main.go:104` with no `Stat` and no lock (`main.go:104-109`), and whether a truncation surfaces as `io.EOF` (`is empty`), a parse error, or a short but successful decode is unclear; need to inspect/test this. Acceptance of the `...` document-end marker is untested in the repo (`main_test.go:179-199` has no such case) and only reproduced against the pinned library. BOM-prefixed configs are likewise untested and undocumented (`README.md:56-77`). Finally, dropping the underlying yaml error for a malformed second document (`main.go:123-124`) is a diagnosability trade-off with no stated rationale in code or docs; unclear; need to inspect git history.

Method note: the edge cases quoted for the library (trailing `---`, `...`, malformed second document, BOM, duplicate keys, type mismatch) were reproduced with a throwaway program in `/tmp` against `go.yaml.in/yaml/v3` v3.0.5, the version pinned at `go.mod:9`; that scratch directory was deleted. No repository file was modified. The repo itself was only read and its test suite executed.
